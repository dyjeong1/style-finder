# Frontend (Next.js)

## 실행 전제
- Node.js 20+
- npm 10+

## 설치/실행
```bash
cd frontend
npm install
npm run dev
```

## 권장 로컬 실행
`next dev`에서 간헐적으로 HMR/캐시 꼬임이 생길 수 있어서, 화면 확인은 아래 명령을 기본으로 권장합니다.

```bash
cd frontend
npm run local
```

- 접속 주소: `http://127.0.0.1:3000`
- 포함 동작: `build` 후 `start --hostname 127.0.0.1 --port 3000`

## 테스트
```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

## 의존성 보안 상태

## 현재 연결된 API 흐름
- `/upload`: `POST /images/upload` 호출 후 현재 업로드를 바로 분석하고 추천 페이지로 이동
- `/recommendations`: `GET /recommendations` 조회 및 `POST /wishlist` 찜 추가
- `/wishlist`: `GET /wishlist` 조회 시 상품명/가격/쇼핑몰/카테고리/링크를 함께 노출하고 `DELETE /wishlist/{product_id}`로 찜 삭제
- 업로드 후 추천 이동 시 `/recommendations?uploaded_image_id=...` 형태의 현재 업로드 ID만 URL로 전달합니다.
- 추천 페이지는 `useSearchParams()` 값이 늦게 들어오는 경우에도 현재 브라우저 URL의 `uploaded_image_id`를 다시 읽어 업로드 기준 상태를 복구합니다.

## UI 개선 사항 (TSK-0003)
- 추천 페이지: 카테고리/정렬/가격 필터, 재조회/필터 초기화, 스켈레톤 로딩, 빈 상태 안내
- 찜 페이지: 카테고리 필터, 재조회, 빈 상태 CTA
- 공통 네비게이션: 업로드 상태 초기화 버튼
- 위시리스트 카드: 상품 썸네일, 카테고리 배지, 가격/쇼핑몰 메타데이터, 이미지 실패 시 대체 썸네일

- 이전 업로드 로컬 상태에 기대지 않아 SSR/CSR 간 업로드 상태 차이를 줄임

## 최근 로컬 실행 안정화

## 최근 추천 복구 개선
- 백엔드 재시작 뒤 오래된 `uploaded_image_id`가 남아 있어도 추천 페이지가 치명적으로 깨지지 않음
- stale 업로드 상태를 자동으로 비우고 `/upload` 재업로드를 안내함

## 최근 최신 업로드 동기화 개선
- 업로드 화면은 현재 업로드 1건만 기준으로 추천 페이지로 이동합니다.
- 추천 페이지는 URL의 `uploaded_image_id`만 사용해 현재 업로드 기준으로 추천을 다시 조회합니다.
- 추천 응답이 돌려주는 `analysis` 요약으로 업로드 분석 패널과 검색 힌트를 다시 동기화합니다.

- 업로드 메인 타이틀은 더 작은 크기로 조정해 화면 균형을 맞춤

## 최근 폰트 단위 정리
- `frontend/app/globals.css`의 폰트 크기 선언을 `pt` 기준으로 정리
- 업로드 화면 메인 타이틀 `.upload-stage-copy h1`은 `36pt`로 적용
- 남아 있던 반응형 `clamp(...)` font-size도 제거해 버튼을 포함한 주요 텍스트를 고정 pt 값으로 정리
- 이후 업로드 화면 메인 타이틀은 `30pt`, 메인 CTA 버튼 텍스트는 `14pt`로 줄이고 버튼 박스도 함께 축소

## 최근 업로드 박스 통합 개선
- 업로드 선택 영역과 미리보기 영역을 하나의 박스로 통합
- 이미지 선택 후 같은 박스 안에서 정사각형 미리보기를 바로 확인 가능
- `사진 삭제` 버튼으로 선택 파일과 상태를 즉시 초기화
- `이미지 분석하기` 버튼은 선택 파일이 있을 때만 활성화
- 같은 박스 안에서 업로드 카피는 상단, 정사각형 미리보기는 하단으로 배치
- 안내 문구를 `클릭하거나 이미지를 끌어다 놓아 주세요.`로 조정
- 허용 형식 안내를 업로드 안내 카피 아래에 `허용 이미지: PNG, JPG, JPEG, WEBP`로 노출

- 업로드 형식 문구를 `허용 이미지: PNG, JPG, JPEG, WEBP`로 조정

- 정적 자산 경로: `frontend/public/brand/stylefinder_logo.png`

## 메뉴 및 페이지 타이틀 한글화
- 상단 메뉴를 `업로드`, `추천`, `위시리스트`로 통일했습니다.
- 업로드/추천/찜 목록 화면의 대표 타이틀과 주요 상단 라벨을 한글로 정리했습니다.
- 브라우저 탭 제목도 화면별 한국어 제목으로 설정했습니다.

## 추천 상품 목데이터 이미지 처리
- 현재 추천 상품은 29CM/지그재그 실 API가 아니라 백엔드 목데이터를 기반으로 표시됩니다.
- 목 이미지 URL이 `example.com`인 경우, 추천/위시리스트 카드에서는 즉시 대체 썸네일을 사용합니다.

## 헤더 초기화 버튼 제거
- 헤더의 `업로드 초기화` 버튼을 제거해 상단 영역을 메뉴 중심으로 단순화했습니다.

## 추천 데이터 소스 표시
- 추천 페이지 상단에 현재 데이터 소스가 `네이버 쇼핑`인지 `샘플 데이터`인지 표시합니다.
- 네이버 API 키가 없으면 자동으로 `샘플 데이터`로 표시됩니다.
- 네이버 API 인증/호출 실패 시 샘플 데이터 fallback 안내 문구를 함께 표시합니다.

## 현재 업로드 단일 세션화
- 업로드 ID, 분석 결과, 업로드 히스토리를 브라우저 localStorage에 저장하지 않습니다.
- 추천 페이지는 현재 URL의 `uploaded_image_id`와 추천 응답의 `analysis`만 기준으로 동작합니다.
- 새 이미지를 업로드하면 이전 업로드 분석 요약과 필터 상태를 즉시 초기화합니다.

## AI 우선 추천 기준 정리
- 업로드 분석 응답에는 `analysis_source`, `query_source` 메타가 포함되어 AI 분석 기준인지 규칙 fallback 기준인지 구분합니다.
- 추천 페이지는 업로드 분석 패널에 `AI 분석 기준` 또는 `fallback 분석 기준`을 직접 표시합니다.
- 감지 품목이 없을 때는 임의 digest 카테고리 대신 빈 카테고리 상태를 유지합니다.
- AI가 빈 결과를 돌려준 경우에는 그대로 AI 결과를 사용하고, provider unavailable/error 상황에서만 규칙 fallback 이 작동합니다.

## 최근 추천 상품 카드 UX 정리
- 추천 카드를 이미지, 상품명, 가격, 상품 보기, 위시리스트 액션 중심으로 재구성했습니다.
- 데이터 출처, 카테고리, 랭킹, 저장 상태는 이미지 위 배지로 간결하게 표시합니다.
- 톤/무드/실루엣/점수 breakdown은 `매칭 정보 보기` 접힘 영역으로 이동해 쇼핑 흐름을 방해하지 않게 정리했습니다.

## 최근 추천 결과 카테고리 섹션화
- 추천 전체 보기에서 상품을 상의/하의/아우터/신발/가방 섹션으로 묶어 표시합니다.
- 각 섹션 헤더에는 상품 개수와 최고 매칭률을 함께 보여줍니다.
- 특정 카테고리 필터를 선택하면 기존처럼 단일 추천 그리드로 표시합니다.

## 최근 추천 카테고리 바로가기
- 추천 전체 보기 상단에 카테고리별 요약/바로가기 바를 추가했습니다.
- 요약 카드에는 카테고리명, 상품 개수, 최고 매칭률을 표시합니다.
- 요약 카드를 누르면 해당 카테고리 섹션으로 바로 이동합니다.

## 최근 추천 검색어 직접 입력
- 추천 필터 영역에서 네이버 쇼핑 검색어를 직접 입력할 수 있습니다.
- `검색어 적용` 또는 Enter 입력으로 직접 검색어 기준 추천을 다시 조회합니다.
- `검색어 초기화`를 누르면 업로드 이미지 분석 기반 자동 검색어로 돌아갑니다.

## 최근 이미지 색상 기반 추천 정확도 개선
- 업로드 분석 타입에 `dominant_color`를 추가했습니다.
- 업로드/추천 화면의 분석 요약과 상품별 매칭 정보에서 색상 신호를 확인할 수 있습니다.
- 상품별 점수 breakdown에는 `color_bonus`가 포함되어 색상이 맞는 상품을 더 위로 올립니다.

## 최근 상품 이미지 직접 분석 추천 정확도 개선
- 추천 매칭 정보에 상품 이미지 대표 색상 신호를 추가했습니다.
- 점수 breakdown에서 상품명 색상 보너스와 상품 이미지 색상 보너스를 분리해 확인할 수 있습니다.

## 최근 카테고리별 코디 검색어 추출
- 추천 검색어가 전체 대표색 하나가 아니라 카테고리별 품목 힌트를 우선 사용합니다.
- 테스트 코디 이미지에서는 `화이트 셔츠`, `화이트 팬츠`, `블랙 니트 베스트`, `브라운 메리제인 슈즈`, `아이보리 숄더백` 검색어로 분리됩니다.

## 최근 검색어 하드코딩 제거
- 추천 검색어가 특정 테스트 이미지 문구를 반복하지 않고, 업로드 이미지의 영역별 색상에 따라 동적으로 생성됩니다.
- `codytest_01.png` 조합은 기존 기대 검색어를 유지하고, 다른 색상 코디는 별도 검색어로 분리됩니다.
