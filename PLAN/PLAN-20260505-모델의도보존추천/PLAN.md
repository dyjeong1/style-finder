## 1. 배경/문제 정의
- 비즈니스 맥락: AI 모델이 업로드 이미지를 보고 `남색 롱슬리브`, `브라운 메리제인`처럼 구체 의도를 반환하면 추천 엔진은 그 의미를 끝까지 보존해야 합니다.
- 현재 성능/운영 이슈: 백엔드 후보 필터와 랭킹 보너스 일부는 문자열 포함 비교와 고정 키워드 사전에 의존해 `롱슬리브 ↔ 긴팔` 같은 동의어 의도를 놓칠 수 있습니다.

## 2. 목표/가설
- 1차 지표(Primary): 모델이 반환한 세부 의도가 후보 필터와 랭킹에 함께 반영된다.
- 2차 지표(Secondary): `롱슬리브`, `긴팔`, `슬리브리스` 같은 동의어가 의미 단위로 정규화된다.
- 가설: 모델 query/item_label의 의미 신호를 동의어 단위로 보존하면 BE 규칙이 모델 의도를 덮어쓰지 않고 더 자연스러운 추천 순서를 만들 수 있다.

## 3. 범위/산출물(Scope & Deliverables)
- 포함 범위:
  - 의도 동의어 공통 매칭 레이어 추가
  - 네이버 후보 필터에 의미 신호 적용
  - 추천 점수의 품목명 보너스를 의미 기반 보너스로 확장
  - 테스트 및 문서 갱신
- 제외 범위:
  - 모델 출력 스키마 자체 변경
  - FE 추천 카드 UI 개편

- 리스크: 동의어 사전이 너무 넓으면 잘못된 후보를 살릴 수 있으므로, 우선 긴팔/반팔/민소매처럼 고신뢰 의도부터 연결해야 합니다.
