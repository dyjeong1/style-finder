## 1. 배경/문제 정의
- 비즈니스 맥락: 추천 페이지 상단 프리뷰는 현재 추천 기준이 되는 실제 업로드 이미지가 있을 때만 보여야 한다.
- 현재 성능/운영 이슈: 업로드가 없을 때도 fallback 썸네일 기반 프리뷰 버튼이 먼저 렌더링되어, 사용자가 아직 분석되지 않은 상태를 업로드 완료 상태로 오해할 수 있다.

## 2. 목표/가설
- 1차 지표(Primary): 업로드 이미지와 분석 결과가 모두 준비된 경우에만 상단 프리뷰가 노출된다.
- 2차 지표(Secondary): 업로드 완료 뒤에는 기존처럼 프리뷰와 확대 모달을 그대로 사용할 수 있다.
- 가설: 프리뷰 노출 조건을 `uploaded_image_id`와 `analysis` 동시 보유 상태로 제한하면 추천 화면의 초기 빈 상태가 더 명확해진다.

## 3. 범위/산출물(Scope & Deliverables)
- 포함 범위:
  - 추천 상단 프리뷰 버튼 조건부 렌더링
  - 확대 모달 조건부 렌더링 정렬
  - 업로드 전/후 프리뷰 노출 회귀 테스트 보강
- 제외 범위:
  - 업로드/추천 화면 디자인 리뉴얼
  - 분석 결과 로딩 흐름 변경
- 산출물(코드/모델/대시보드/문서):
  - `frontend/app/(main)/recommendations/page.tsx`
  - `frontend/e2e/core-flow.spec.ts`
  - 관련 PLAN/TASK/README/TODO 문서
