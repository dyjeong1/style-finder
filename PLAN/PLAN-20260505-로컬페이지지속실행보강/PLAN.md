## 1. 배경/문제 정의
- 비즈니스 맥락: 로컬에서 업로드/추천 페이지를 바로 열어 확인하는 흐름이 개발 속도에 직접 영향을 줍니다.
- 현재 성능/운영 이슈: 프론트 `3000`과 백엔드 `8000`이 동시에 떠 있지 않으면 페이지가 열리지 않고, 실행 절차가 분산되어 있어 재시작과 유지가 번거롭습니다.

## 2. 목표/가설
- 1차 지표(Primary): 한 번의 명령으로 프론트/백엔드가 함께 떠서 페이지가 계속 열리는 로컬 실행 경로를 제공한다.
- 2차 지표(Secondary): 실행 상태, 로그 위치, 중지 방법을 함께 표준화해 재현성을 높인다.
- 가설: PID/로그를 관리하는 로컬 스택 스크립트를 추가하면 페이지 미오픈 이슈를 줄이고 개발 진입 비용을 낮출 수 있다.

## 3. 범위/산출물(Scope & Deliverables)
- 포함 범위:
  - 로컬 프론트/백엔드 시작 스크립트 추가
  - 상태 확인 및 중지 스크립트 추가
  - 관련 문서와 루트 README/TODO 갱신
- 제외 범위:
  - 배포 환경 프로세스 매니저 도입
  - 원격 서버 운영 자동화
