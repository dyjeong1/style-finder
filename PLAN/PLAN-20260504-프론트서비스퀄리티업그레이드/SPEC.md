## 1. 목적
기존 기능 흐름을 유지하면서도 StyleMatch 프론트가 실제 서비스처럼 보이고 느껴지도록 화면 구성, 타이포그래피, 상호작용 품질을 끌어올립니다.

## 2. 시각 스펙
- 비주얼 테마: 따뜻한 스튜디오 톤 위에 잉크 네이비를 축으로 쓰는 편집숍형 인터페이스
- 업로드 화면: 큰 브랜드 메시지, 1개의 강한 업로드 무대, 보조 신뢰 정보
- 추천 화면: 업로드 분석 요약 + 탐색 필터 + 카테고리별 큐레이션 섹션
- 위시리스트 화면: 저장 컬렉션 보드형 구조, 정렬/필터와 CTA의 명확한 분리

## 3. 인터랙션 스펙
- 공통 배경과 포인트 오브젝트에 느린 부유 애니메이션을 적용합니다.
- 네비게이션/히어로/핵심 CTA는 진입 시 순차 등장 애니메이션을 사용합니다.
- 상품 카드와 주요 탐색 요소에는 hover lift, border glow 등 명확한 affordance를 부여합니다.

## 4. 구현 스펙
- `frontend/components/app-shell.tsx`: 브랜드 헤더를 서비스형으로 재구성하고 현재 화면 컨텍스트를 노출
- `frontend/app/globals.css`: 전역 토큰, 레이아웃, 편집숍형 섹션, 반응형 규칙 재정의
- `frontend/app/(main)/upload/page.tsx`: 업로드 무대와 신뢰/진행 정보 재배치
- `frontend/app/(main)/recommendations/page.tsx`: 추천 요약, 필터, 큐레이션 섹션, 빈 상태 리디자인
- `frontend/app/(main)/wishlist/page.tsx`: 저장 보드형 리스트와 관리 액션 재정리

## 5. 비기능 스펙
- 기존 API 호출 방식과 상태 흐름은 유지합니다.
- 이미지 업로드/추천/위시리스트 기능 동작을 깨지 않아야 합니다.
- 데스크톱과 모바일 모두에서 첫 화면 주요 CTA가 첫 스크린 안에 들어와야 합니다.

## 6. 수용 기준
- [x] 브랜드/제품 성격이 첫 화면에서 즉시 드러남
- [x] 추천 탐색 구조가 필터 중심 도구 화면이 아니라 큐레이션 서비스처럼 보임
- [x] 위시리스트가 저장 상품 재탐색에 적합한 구조를 가짐
- [x] `cd frontend && npm run build` 통과
