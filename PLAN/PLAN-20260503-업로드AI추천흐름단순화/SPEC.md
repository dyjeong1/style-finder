## 제품 동작 기준
1. 유저가 이미지를 업로드한다.
2. AI 비전 분석기가 현재 업로드 이미지를 분석한다.
3. 분석 결과를 바탕으로 유사 상품 추천을 생성한다.
4. 유저가 새 이미지를 업로드하면 이전 업로드 분석 상태는 즉시 초기화한다.
5. 업로드 분석 상태는 localStorage 같은 프론트 영속 저장소에 남기지 않는다.
6. AI 분석이 실패하거나 결과가 비어 있을 때만 규칙 분석기를 마지막 fallback 으로 사용한다.

## 정리 대상
- `stylematch_uploaded_image_id`
- `stylematch_uploaded_image_analysis`
- `stylematch_upload_history`
- 업로드 재사용/최근 업로드 분석 동기화 로직
- AI 결과와 규칙 결과가 동시에 최종 노출되는 중간 병합 잔재

## 유지 대상
- 위시리스트
- 네이버 쇼핑 추천 조회
- AI 결과 기반 `category_query_hints`
- 추천 결과/분석 결과 노출 UI 자체

## 구현 원칙
- 프론트는 "현재 업로드 1건" 상태만 메모리 기준으로 유지한다.
- 추천 페이지는 URL이나 로컬 저장 상태보다 현재 업로드 응답/추천 응답을 우선 신뢰한다.
- 백엔드는 AI 성공과 fallback 경로를 명시적으로 분리한다.
- fallback 이유는 로그나 응답 메타에서 추적 가능해야 한다.

## 테스트 기준
- 업로드 A 이후 업로드 B를 수행하면 A 분석 상태가 화면/로컬 저장소에 남지 않는다.
- AI provider 정상 시 규칙 분석 결과가 최종 추천 검색어를 오염시키지 않는다.
- AI provider 실패 시에만 규칙 분석 결과가 노출된다.
