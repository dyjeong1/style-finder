## 1. 요구사항
1. 최근 업로드 목록을 `/upload` 화면에 다시 노출한다.
2. 분석 결과는 저장하지 않고, 업로드한 이미지 파일만 브라우저에 저장한다.
3. 최근 업로드 카드를 누르면 저장된 이미지를 다시 업로드해 새 분석을 시작한다.
4. 최근 업로드 항목은 개별 삭제할 수 있어야 한다.

## 2. 저장 정책
- 저장 대상:
  - 이미지 blob
  - 파일명
  - MIME type
  - 생성 시각
  - 크기(byte)
- 저장 제외:
  - `uploaded_image_id`
  - 분석 요약
  - 추천 결과
  - 검색어/필터 상태
- 저장 위치:
  - 브라우저 `IndexedDB`
- 보관 개수:
  - 최신 8개 유지

## 3. UI/UX 규칙
- 최근 업로드 카드는 썸네일, 파일명, 업로드 시각, `다시 분석` 성격의 보조 문구를 가진다.
- 카드 클릭 시 저장된 이미지를 즉시 재업로드하고 추천 페이지로 이동한다.
- 카드 내부 삭제 버튼은 재사용 클릭과 충돌하지 않아야 한다.
- 업로드 중에는 최근 업로드 카드도 비활성화한다.

## 4. 오류 처리
- 저장된 이미지를 읽을 수 없으면 해당 항목을 목록에서 제거하고 에러 문구를 보여준다.
- `IndexedDB` 접근이 불가능하면 최근 업로드 기능만 비활성화하고 기본 업로드 흐름은 유지한다.
- 최근 업로드 재사용 중 업로드 API가 실패하면 일반 업로드 실패 메시지와 동일한 문구를 사용한다.

## 5. 검증 시나리오
- `/upload`에서 새 이미지를 업로드한 뒤 다시 `/upload`로 돌아오면 최근 업로드 카드가 보인다.
- 최근 업로드 카드를 눌렀을 때 새 `uploaded_image_id`로 추천 페이지가 열린다.
- 업로드 관련 `localStorage` 키는 계속 비어 있다.
- 최근 업로드 카드 삭제 후 목록에서 즉시 사라진다.
