## 1. 배경/문제 정의
- 비즈니스 맥락: 사용자가 자주 같은 코디 이미지를 다시 확인할 수 있어야 추천 흐름의 재진입 부담이 줄어든다.
- 현재 성능/운영 이슈: `PLAN-20260503-업로드AI추천흐름단순화`에서 최근 업로드 UI와 영속 상태를 제거하면서, 사용자가 매번 파일을 다시 선택해야 하는 불편이 생겼다.

## 2. 목표/가설
- 1차 지표(Primary): `/upload`에서 최근 업로드 이미지를 다시 눌러 새 분석을 시작할 수 있다.
- 2차 지표(Secondary): 분석 결과는 저장하지 않고도 최근 업로드 재사용이 가능하다.
- 가설: 브라우저에 업로드 이미지 파일만 저장하고, 카드 클릭 시 해당 이미지를 다시 업로드하면 단일 분석 원칙을 유지하면서도 재사용 UX를 복원할 수 있다.

## 3. 범위/산출물(Scope & Deliverables)
- 포함 범위:
  - 업로드 이미지 전용 브라우저 저장소 추가
  - 최근 업로드 목록 UI 복원
  - 최근 업로드 카드 클릭 시 재분석 흐름 연결
- 제외 범위:
  - 분석 결과 영속 저장
  - 서버 측 업로드 이력 보관
- 산출물(코드/모델/대시보드/문서):
  - `frontend/lib/recent-upload-store.ts`
  - `frontend/app/(main)/upload/page.tsx`
  - `frontend/app/globals.css`
  - `frontend/e2e/core-flow.spec.ts`
  - 관련 PLAN/TASK/README/TODO 문서

- 시스템/리소스 제약: 이미지 원본을 브라우저에 계속 쌓지 않도록 개수 제한이 필요하다.
